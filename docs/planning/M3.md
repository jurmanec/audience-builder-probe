# M3 roadmap

M3 is the one-shot path, then a scored comparison of all three paths. The template path and the graph stay as they are. Decision notes are written from the scores. The public README is last. v1 is complete when this milestone is done.

The one-shot path receives an objective string. It makes one structured model call, counts that predicate once, and returns a draft audience or nothing. It does not revise. It does not read `eval/gold.json`, and it does not import the template intents. The eval harness may read the gold file. It does not edit it.

## 1. One model call, one count

One function accepts the objective and the usable attribute guide: name, type, operators, and any enum values or integer bounds. It returns one predicate in the shared schema. Code sets `estimated_size` from one `count_audience` call and sets `status` to `draft`.

The call does not receive a gold band, a prior attempt, or a template predicate. A count of 0, a count above 2,500, a tool rejection, or a response that is not a predicate returns nothing. There is no second call.

The default provider is xAI model `grok-4.7`, the same id as the graph. The API key is read from the environment or from `.env`. A missing key makes no request. Tests pass a scripted predicate, so the milestone does not require a network call. Bedrock stays a later swap.

## 2. Write a file only after success

A small runner takes an objective string. A completed call may write the draft audience. A miss, a rejection, or a schema failure writes no audience file and no brief file.

The runner does not approve an audience and does not write a brief. The existing brief step stays where it is: an approved audience and a known campaign. The three-way score does not score briefs.

A short how-to says how to run the one-shot command and where the log is written.

## 3. Score all three paths

One harness runs the template path, the one-shot path, and the graph on all eight gold objectives. Each path receives only what it already accepts: an intent name, or an objective string. None of the paths open the gold file.

The score is deterministic and local. It does not call a judge model.

- An objective with `outcome: no_audience` passes only when that path writes no audience file and no brief file.
- Every other objective passes only when the file is a draft audience, `estimated_size` is inside `size_band`, every predicate field is one of `attribute_families`, and no predicate field is one of `forbidden_fields`.
- A file for a `no_audience` objective fails. A missing file, a size outside the band, a field outside the families, or a forbidden field fails.

Tests inject scripted predicates for the one-shot path and the graph. The command that records the score uses `grok-4.7` when `XAI_API_KEY` is set. A missing key writes no score file. `eval/gold.json` stays unchanged. Do not edit a label to make a path pass.

## 4. Decision notes

Write the notes after the recorded score exists. State where the graph passes and the template does not, and where a template passes and the graph does not. The one-shot column is part of that comparison.

The notes may use the live runs already on disk. `g07` is one case: the gold outcome is no audience, and a live graph run wrote a tenure predicate of size 2300. Record that from the score. Do not change the graph or the label to remove it.

The catalog stays the frozen slice. Widen it only by reopening M0, and only if the scores cannot separate the paths.

## 5. Public README

The README is the v1 runbook. It tells how to run all three paths, which tools exist, where `logs/tool.jsonl` is written, and what a failed run looks like. It uses illustrative marketing-ops vocabulary only.

The public project name chosen in this step is Audience Builder Probe. The README does not include the charter, the gold file, or the private notes.

## Done when

The one-shot path returns a draft audience or nothing, with one count and no revision. The score covers all eight objectives on all three paths, and a failing score does not change `eval/gold.json`. Decision notes say where the graph wins and where a template wins. The README runbook exists. No second model provider, no OpenTelemetry, and no UI.
